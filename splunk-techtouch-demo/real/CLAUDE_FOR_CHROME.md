## 貼り付ける指示（ここから下をすべてコピー）

あなたは、Splunk Cloud（このタブ）とテックタッチ（もう一つのタブ）を操作して、営業用デモ動画の第3章の画面を準備します。次の順に進めてください。各段階の終わりに、何をしたかを短く報告してください。迷った箇所や、権限がなくて進めない箇所は、勝手に回避せず止まって知らせてください。

### A. サンプルログを入れる（Splunk）

1. 設定 ＞ インデックス で、イベントインデックス `app_logs` を新規作成します（作成できない場合は止まって知らせてください。代わりに `main` を使うかどうかを確認します）。
2. 検索とレポート（Search & Reporting）の検索画面で、次の SPL を **1回だけ** 実行します。今日の 09:30〜10:30 の架空ログ（約6,000件）を `app_logs` に書き込みます。2回実行すると件数が倍になります。

```
| makeresults count=6000
| eval base=relative_time(now(),"@d")+34200
| eval _time=base+(random()%3600)
| eval m=floor((_time-base)/60)
| eval r=random()%1000
| eval log_level=case(m<30 AND r<8,"ERROR", m>=30 AND r<min(300,(m-29)*35),"ERROR", r>=970,"WARN", true(),"INFO")
| eval r2=random()%100
| eval error_code=if(log_level="ERROR", case(m>=35 AND r2<40,"POOL_EXHAUSTED", r2<94,"DB_CONN_TIMEOUT", true(),"CONN_RESET"), null())
| eval service="contract_inquiry", server=if(random()%2=0,"ctr-app-01","ctr-app-02")
| eval message=case(error_code="DB_CONN_TIMEOUT","connection timeout to ctr-db-01", error_code="POOL_EXHAUSTED","connection pool exhausted (max=500)", error_code="CONN_RESET","connection reset by peer", log_level="WARN","slow response from contract api", true(),"request completed")
| fields _time service server log_level error_code message
| collect index=app_logs
```

3. 数十秒待ってから、次の SPL で書き込めたことを確かめ、結果（error_code ごとの件数）を報告します。

```
index=app_logs service="contract_inquiry" log_level=ERROR earliest=@d+9h30m latest=@d+10h30m
| stats count by error_code
```

`collect` の権限がなくて実行できない場合は、止まって知らせてください。

### B. SPL のひな型をレポートとして保存する（Splunk）

1. 検索画面で次の SPL を入力し、時間範囲を「今日の 09:30〜10:30」（日付と時刻の範囲）にして検索します。

```
index=app_logs service="contract_inquiry" log_level=ERROR
| search message="*connection*"
| timechart span=5m count by error_code
```

2. 視覚エフェクトのタブで、グラフの種類を「折れ線グラフ」にします。10:00 ごろから DB_CONN_TIMEOUT が増え、10:05 ごろから POOL_EXHAUSTED が出ていれば正しい状態です。
3. 「名前を付けて保存 ＞ レポート」で、次の内容で保存します。
   - タイトル：`接続エラーの推移（標準）`
   - 説明：`専門チームが確認済みのひな型（デモ用）`
   - 時間範囲ピッカー：表示する
4. 同じ要領で、ダミーのレポートを2件保存します（一覧を本物らしく見せるため）。
   - `エラーの内訳（標準）`：`index=app_logs log_level=ERROR | stats count by error_code`
   - `遅い処理の上位（標準）`：`index=app_logs log_level=WARN | stats count by server`

### C. テックタッチのガイドを作る（テックタッチのタブ）

Splunk の「検索とレポート」の画面を対象に、ガイド「ログをひな型から調べる」を作ります。吹き出しの文言は下のとおりです。画面の実際の表記（日本語の UI 名）と違う場合は、実際の表記に合わせてください。

| # | 表示する画面 | 指す場所 | 吹き出しの文言 |
|---|---|---|---|
| 1 | 検索画面 | アプリバーの「レポート」 | ①「レポート」を開きます。専門チームが作ったSPLのひな型が保存されています |
| 2 | レポート一覧 | 「接続エラーの推移（標準）」の「サーチで開く」（Open in Search） | ② 確認済みのひな型を、検索画面で開きます |
| 3 | 検索画面 | 検索バー（SPL） | ③ 検索の中身（SPL）を確認します |
| 4 | 検索画面 | 時間範囲ピッカー | ④ 時間範囲を、障害の開始（10:02）を含む 09:30〜10:30 にします |
| 5 | 検索画面 | 検索ボタン（虫めがね） | ⑤ 検索を実行します |
| 6 | 検索画面 | ジョブの「共有」 | ⑥ 結果を共有して、専門チームに確認を依頼します |
| 7 | 検索画面 | 「名前を付けて保存」 | ⑦ レポートとして保存し、運用チームに共有します |

- AI Hub が使える環境なら、ステップ3に「SPL を1行ずつ説明する」AI Hub の表示を付けます（使えない場合は付けずに知らせてください。動画側で「AI Hub（構想）」として重ねます）。
- 作ったガイドは「公開」にして、Splunk の画面上で再生できる状態にしてください（デモの主役なので、編集画面ではなく再生画面で見せます）。

ガイドを最初から再生し、次の各場面で **止まって「スクショをどうぞ（r01）」のように知らせてください**。木村さんが撮ったら「次」と言うので、次の場面へ進みます。

## 注意

- ログはすべて `makeresults` で作った架空データです。お客様の環境・データは使いません。
- `collect` で書き込んだデータは簡単には消せません（削除には専用の権限が要ります）。やり直す場合は、別名のインデックス（例：`app_logs2`）を作り、SPL のインデックス名を差し替えます。
- 動画では、第3章を「Splunk Cloud 実画面（デモ環境・サンプルデータ）」と表示し、第1・2章の架空画面と区別します。

## 撮り直し用の短い指示（ガイド作成後）

```
テックタッチのガイド「ログをひな型から調べる」を、デモで見せられる状態にして再生してください。
1. 管理画面で、このガイドを「公開」にする。
2. 吹き出しの文言が初期値（「クリックしてください」など）のままのステップを、指示書の表の文言に直して保存する。特にステップ④（時間範囲）。
3. Splunk の検索画面を開き、テックタッチのウィジェットからこのガイドを選んで、最初から再生する。編集画面（ガイドエディター）は使わず、利用者に見える再生の画面で進める。
4. 吹き出しが出るたびに止まり、「スクショをどうぞ（r02）」のように知らせる。私が「次」と言ったら次へ進む。
   r01：ウィジェットのガイド一覧に「ログをひな型から調べる」が見えている状態
   r02 以降：吹き出しが出るたびに1枚（順番どおりに番号を振る）
   最後：ガイドが完了した状態
5. ウィンドウの大きさは撮影中に変えない。
```
