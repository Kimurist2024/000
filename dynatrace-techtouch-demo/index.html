この章の進め方

  • 仮説1「画面・操作で迷う」への支援案（テックタッチのガイド）。p.11に対応します。
  • 見せ場：ガイド一覧から開始 → Dockで画面を探す → サービス・時間枠・比較期間をそろえる → 「?」で社内の指標定義（架空）を表示。
  • 比較期間に「09:00–10:00」を選ぶと、ガイドが選び直しを案内します（構想の表現）。
  • 最後に、同じ時間帯に検知された問題から第2章へつなぎます。
  • 問いかけ：「どこで迷いますか」
  • 仮説4「実務で再現できない」・仮説5「学びを再利用できない」への支援案（テックタッチのステップガイド）。p.12に対応します。
  • 4ステップ：概要 → 影響範囲（優先度の基準を表示）→ 関連ログ（期間は問題の開始5分前から）→ 社内手順に沿って連絡。
  • 影響範囲の前に「ログ」タブを開くと、社内手順の順番を案内します（構想の表現）。
  • 社内手順・連絡先は架空です。お客様の実際の手順に置き換える前提です。
  • 問いかけ：「人によって手順がばらつくのはどこですか」
  • 仮説3「作成・修正で止まる」への支援案（ひな型編集の案内＋AI Hub＋Dynatrace Assist）。p.13に対応します。
  • 見せ場：ひな型から作成 → 変える項目と理由（AI Hub欄は例文）→ 専門家に確認を依頼 → 承認後に保存して共有。
  • Dynatrace Assistの利用状況（利用条件を満たすか）も伺います。
  • 問いかけ：「どこで依頼しますか」
  • 振り返りの回数は、このデモを操作した回数です。効果の数値ではありません。
  • p.14「本日伺いたいこと」、p.15「最初の一歩のご提案」へつなげます。

全体

  • 冒頭で「構想デモです。画面・サービス名・手順・数値は架空で、実際の製品画面や連携動作を示すものではありません」とお伝えする。
  • 問い合わせ → 状況確認 → 一次確認・連絡 → 再発への備え、を一つの業務の流れとして見せます。章の終わりごとに止めて質問できます。
  • デモはテックタッチ（DAP）中心。仮説2（AI Hubの理解支援）は専用デモを持たず、p.8の支援案で説明します。
  • 削減率などの数値はお約束しない。確かめ方は自力完了率・所要時間・依頼件数・再実行。

想定問答

  • 「実際のDynatrace画面で動きますか」→ iframe構成の画面でも動作します。御社環境での確認は導入時に実施します。
  • 「Dynatrace Assistと何が違いますか」→ Assistは公式情報・環境データを使う支援です。AI Hubは御社の社内資料側の知見を補う構想で、重複する部分はDynatraceの機能を優先します。
  • 「効果はどれくらいですか」→ 現時点で数値はお約束しません。一つの作業で、自力完了率・所要時間・依頼件数を測って確かめます。
  • 「セキュリティは」→ 拡張機能の配布手続きと、AI Hubに渡す情報の範囲を御社方針に沿って決めます。AI Hubは外部のAIサービスを利用します。
